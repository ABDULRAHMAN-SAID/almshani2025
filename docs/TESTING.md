# الاختبار — النموذج ثلاثي الأبعاد

لا مترجم C# هنا؛ التحقق كله في **Chromium بلا رأس** عبر Playwright مع عرض برمجي (SwiftShader). العرض بطيء (2–5 إطارات/ث) فتُستخدم نسخة `t3dfast.html` التي تشغّل المحاكاة ×6 لكل إطار.

## الأدوات

| الملف | الغرض |
|---|---|
| `mktests.py` | يولّد `t3d.html` (Three محلي + خطاف `window.__d`) و`t3dfast.html` و`game3d.js` |
| `node --check game3d.js` | الفحص النحوي |
| `errtrace.js` | تحميل الصفحة ورصد `pageerror` مع المكدس |
| `dbgsel.js` | اختيار كل نوع عقدة والتحقق من البطاقات |
| `p1test.js` | التدفق الكامل: قفل المباني، ترقية القلعة، معاينة الموجة، ليلة كاملة، تقرير الفجر |
| `bossfast.js <ذهب> <مبانٍ> <أسوار>` | ليلة الزعيم بتشكيلة محددة (توازن) |
| `t3drunfast.js` | حملة متعددة الليالي |
| `shot3.js` / `shot4.js` | لقطات: افتراضي، بعيد، القائد، الأعداء، الليل |
| `mobile.js` / `thumbs.js` | 844×390 باللمس، وصور البطاقات |
| `fulltest.js` | التدفق الكامل على النسخة المجمّعة: تجهيز ← بناء ← إيقاف/إعدادات ← تكبير ← ليلة ← تقرير ← حفظ ← حملة ← هزيمة ← إعادة الليلة ← قدرة السلاح |
| `locktest.js` | قفل الهدف بالضغط المطوّل (قفل، إلغاء، إعادة قفل) |
| `bossfast2.js <ذهب> <مبانٍ> <أسوار>` | ليلة الزعيم على العقد المصنّفة مع ترقية القلعة (توازن) |
| `shot5.js` | لقطات الواجهات الجديدة: التجهيز، اللوحة الجانبية، الإيقاف، الحملة، نظرة الخريطة، عنوان الليلة |

## خطاف الاختبار `window.__d`

`state()`, `slots()` (بالنوع), `walls()`, `near()`, `cam()`, `spawnAll()`, `set(wave,silver)`, `hero()`, `night(bool)`, `pickAt(x,y)`, `sel()`, `info()`. الوحدات تضيف خطّافاتها عند وجود `window.__d`.

## التشغيل محلياً

```
cd docs/prototype/tests && npm i three@0.128.0 playwright   # مرة واحدة
python3 mktests.py            # يولّد t3d.html / t3dfast.html / game3d.js من ../dawnkeep-3d.html
node --check game3d.js && node fulltest.js
```

المصادر في `docs/prototype/src/` (النواة `dk3d.core.html` + أربع وحدات + `assemble.py` الذي يولّد `dawnkeep-3d.html`). النواة هي مصدر الحقيقة (لم تعد تُولَّد من رقع)؛ أي تعديل يُكتب عليها مباشرة أو كرقعة فوقها.

## قواعد

- افتح الصفحة بـ `{waitUntil:'commit'}` ثم `waitForSelector('#ovBtn',{timeout:240000})` — الخطوط الخارجية محجوبة في البيئة السحابية فلا ينتهي حدث `load`.
- أي `pageerror` = فشل.
- الضغط المطوّل في الاختبارات: امسك 700ms على الأقل. المؤقّت قد يتأخر خلف إطار بطيء، لذا يُحتسب الإفلات بعد 480ms بلا سحب ضغطاً مطوّلاً أيضاً.
- أرقام التوازن المرجعية بعد الوثيقة الرئيسية (`bossfast2.js` على `t3dfast.html`، لاعب آلي سلبي يلاحق أقرب عدو بلا أوامر ولا قدرات): ليلة الزعيم «حارس الرماد» بموجة 33 (14 غازي، 4 مدرّع، 8 ناهب، 6 خفّاش + الزعيم):
  - 5 مبانٍ (برجان، كوخان، ثكنة) + قلعة L2 بلا أسوار → الحصن 2800→1947 وكل المباني مدمّرة عند نهاية الموجة تقريباً (بقي 5 أعداء). أي: نجاة بالكاد، وخسارة المملكة — وهو المقصود لمن لا يستثمر.
  - 9 مبانٍ (4 أبراج رماة، برج نار، ثكنتان، كوخان) + سوران + قلعة L3 → الحصن 3500→3319 وبقاء 5 مبانٍ من 9 عند نهاية الموجة تقريباً. أي: نجاة مريحة بخسائر متوسطة.
  - على الخريطة العضوية (عالم 2600، سور 140، أعداء ×2.6): 9 مبانٍ + سوران + قلعة L3 → الحصن 3500 سليماً و8 مبانٍ من 9 عند t+600ث من الموجة (اللاعب الآلي يطارد أقرب عدو فقط).
  - على الخريطة العضوية: 5 مبانٍ بلا أسوار + قلعة L2 → الحصن 2800→2772 عند t+784ث لكن النجوع الخارجية تُدمَّر (بقي مبنيان من 5) — الأعداء البطيئون يلتهمون الاقتصاد المكشوف قبل أن يبلغوا القلعة، وهو المقصود: السور والأبراج عند البوابات ضرورة لا رفاهية.
  - خطوة «ضرب القائد» في `fulltest.js` تعدّ المقتولين مع المصابين: القائد بسيف +35% يقتل الغازي بضربة واحدة فيختفي من القائمة.
  - القياس قبل التخفيف (موجة 47): سقوط الحصن كاملاً حتى مع قلعة L3 — لذلك خُفّفت حشود الليالي 3–6 بنحو 25–35%.
- التشغيل المتوازي لمتصفحين على جهاز الاختبار (نواتان) يُسقط النقرات بمهلة 30 ثانية — شغّل الاختبارات الثقيلة متسلسلة.

## على جهاز المستخدم

افتح `docs/prototype/dawnkeep-3d.html` في متصفح حديث أو الرابط المنشور. تأكد من: المقدمة ← التجهيز ← البناء (لوحة جانبية) ← ابدأ الليلة (عنوان 3 ثوانٍ) ← القتال ← تقرير الفجر. زر ⏸ للإيقاف والإعدادات.
