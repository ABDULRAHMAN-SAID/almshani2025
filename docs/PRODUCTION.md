# النسخة النهائية — كل شيء حقيقي

هذا الملف لطريق واحد: تطبيق يُثبَّت على الهواتف، يدخل الناس فيه **برقمهم ورمز SMS حقيقي**،
ويكتبون ويرفعون **صورًا ومقاطع وملفات تُحفظ على خادمك** ويراها بقية المستخدمين.

ليس فيه تجربة ولا بيانات وهمية.

---

## الفرق بين النسختين — اقرأه أولًا

| | نسخة العرض | **النسخة النهائية** |
|---|---|---|
| الأمر | `npm run make-app -- --demo` | `npm run make-app` |
| الدخول | أي رقم وأي رمز | رقمك الحقيقي + رمز تحقّق من الخادم |
| ما تكتبه | يبقى في ذاكرة هاتفك | يُحفظ على خادمك |
| الصور والمقاطع | لا تُرفع | تُرفع وتُحفظ ويراها الآخرون |
| يراه غيرك | لا | نعم |
| عند حذف التطبيق | يضيع كل شيء | لا يضيع شيء |
| تحتاج خادمًا | لا | **نعم** |

نسخة العرض تنفع لتُري أحدًا شكل التطبيق. لا توزّعها على أنها التطبيق: كل جهاز فيها جزيرة وحده.

## الخطوة 1 — ابنِ الخادم بأمر واحد

```bash
npm run setup
```

يطلب منك شيئًا واحدًا: **رمز وصول** من حسابك في Supabase.

1. افتح [supabase.com/dashboard/account/tokens](https://supabase.com/dashboard/account/tokens)
2. سجّل الدخول، أو أنشئ حسابًا مجانيًا (دقيقة).
3. **Generate new token** ← سمِّه `anshatati` ← انسخه.
4. الصقه في النافذة.

> الرمز يظهر مرة واحدة فقط. وهو يفتح حسابك في Supabase كاملًا، فلا ترسله لأحد.
> يُحفظ على جهازك في `.supabase-setup.json` ولا يدخل المستودع ولا يُرفع مع
> البناء. ولحذفه: `npm run setup -- --forget`

ثم يفعل الباقي وحده، ست مراحل:

| | ما يفعله |
|---|---|
| 1 | يقرأ حسابك ومؤسستك |
| 2 | ينشئ المشروع (أو يستعمل واحدًا موجودًا تختاره) |
| 3 | ينتظر جهوزية القاعدة — دقيقتان |
| 4 | يركّب المخطط كاملًا، ثم يملأ القاعدة بمحتوى البداية |
| 5 | يفعّل الدخول بالهاتف، ويضع لك **رمز دخول ثابتًا** يعمل سنة بلا رسائل |
| 6 | يجلب المفتاح العام ويكتب `.env` |

**احفظ الرمز الثابت الذي يطبعه في آخر المرحلة 5** — به تدخل التطبيق.

### إن تعثّرت أي مرحلة

لا تتوقف الأداة صامتة: تطبع الخطوة اليدوية المكافئة لتلك المرحلة وحدها، وما تمّ
قبلها يبقى تامًّا. أعد `npm run setup` بعد إصلاحها فيكمل من حيث وقف.

## الطريق اليدوي — إن فضّلته أو تعثّر الأمر

<details>
<summary>افتحه إن احتجته</summary>

**1. أنشئ المشروع.** [supabase.com](https://supabase.com) ← **New project**.
المنطقة **Central EU (Frankfurt)** هي الأقرب لعُمان. احفظ كلمة مرور القاعدة.

**2. ركّب البنية.** **SQL Editor ← New query**: الصق محتوى `supabase/schema.sql`
**كاملًا** ← **Run**. ثم كرّرها مع `supabase/starter-content.sql` (اختياري — يملأ
التطبيق بمقالات وأنشطة ومجموعات ومسابقة بدل أن يفتح فارغًا).

> إن ظهر خطأ بالمنتصف فالغالب أنك نسخت جزءًا من الملف. أعد النسخ من أوله إلى آخره.

**3. فعّل الدخول بالهاتف.** **Authentication ← Sign In / Providers ← Phone** ← فعّله.

Supabase لا يرسل الرسائل بنفسه. أمامك طريقان:

- **للتجربة اليوم بلا دفع — Test OTP.** في الصفحة نفسها أضف رقمك ورمزًا ثابتًا من
  ستة أرقام: `+96891234567 → 123456`. يدخل هذا الرقم بهذا الرمز بلا أي رسالة.
  والدخول حقيقي: الحساب يُنشأ فعلًا، وكل ما يكتبه يُحفظ ويظهر للآخرين.
- **للتوزيع الفعلي — مزوّد رسائل.** حساب في [Twilio](https://twilio.com) برصيد،
  ومفاتيحه في نفس الصفحة. الرسالة إلى عُمان بسنتات قليلة.

**4. اربط التطبيق.**

```bash
npm run connect
```

يسأل عن **Project URL** و**anon public** من **Settings ← API**، يكتب `.env`،
ثم يجرّب الاتصال فورًا ويطبع ما وجده على خادمك.

> يرفض المفتاح السرّي (`service_role`) رفضًا صريحًا. لا تضعه في التطبيق أبدًا:
> التطبيق يُوزَّع كملف، ومن يفتحه يقرأ ما فيه.

## الخطوة 2 — ابنِ النسخة النهائية

```bash
npm run make-app
```

خمس مراحل تعمل وحدها. ما يُطلب منك خلالها:

| السؤال | جوابك |
|---|---|
| تسجيل الدخول في Expo | اسم المستخدم وكلمة المرور (الكلمة لا تظهر أثناء الكتابة — طبيعي) |
| `Which account should own this project?` | اضغط Enter |
| `Generate a new Android Keystore? › (Y/n)` | اضغط `Y` ثم Enter |

ثم انتظر 10–20 دقيقة. لا تغلق النافذة.

قبل أن يبني، يسأل الأمر خادمك: هل الجداول والدوال والحاويات موجودة فعلًا؟
**إن لم تكن، يتوقف ولا يبني شيئًا** — فلا يخرج ملف يبدو سليمًا وهو معطّل.

في النهاية يعطيك رابطًا. افتحه، اضغط **Download**، ينزل ملف `.apk`.

## الخطوة 3 — عيّن نفسك إداريًا

لوحة الإدارة لا تُفتح برمز. الخادم هو الذي يقرّر، وقراره مبني على جدول `admins`.

1. ثبّت الـ`.apk` على هاتفك وسجّل دخولك مرة واحدة.
2. من الحاسوب:

```bash
npm run admin
```

3. أغلق التطبيق وافتحه: تظهر لوحة الإدارة.

أوامر أخرى:

```bash
npm run admin -- --list             # من هم الإداريون الآن؟
npm run admin -- +96891234567       # رقّ شخصًا آخر
npm run admin -- --remove +968…     # اسحب الصلاحية
```

> **يدويًا:** افتح `supabase/make-me-admin.sql`، ضع رقمك في السطر المعلَّم، ثم
> الصقه في **SQL Editor** ← Run.

> الترقية من خارج التطبيق دائمًا، لا من داخله. لو أمكنت من داخله لكان اختراق
> حساب إداري واحد كافيًا لصناعة إداريين آخرين.

## الخطوة 4 — تحقّق قبل أن توزّع

جرّب هذا بنفسك على هاتفك، بالترتيب:

- [ ] سجّل دخولك برقمك، واستقبل الرمز فعلًا.
- [ ] اكتب اسمك في إعداد الملف الشخصي، ثم أغلق التطبيق وافتحه: هل بقي الاسم؟
- [ ] انشر في مجموعة نقاشية وأرفق **صورة**.
- [ ] أرسل رسالة إلى الإدارة وأرفق **ملفًا**.
- [ ] سجّل **مقطعًا صوتيًا** وأرفقه.
- [ ] صوّر **مقطع فيديو** قصيرًا وأرفقه.
- [ ] من هاتف آخر بحساب آخر: هل يظهر منشورك وصورتك عنده؟ ← هذا هو الاختبار الفاصل.
- [ ] لوحة الإدارة ← الإعدادات ← **فحص الربط**: كل الأسطر خضراء.
- [ ] لوحة الإدارة: أنشئ نشاطًا، أرسل إشعارًا، ثبّت منشورًا.

السطر قبل الأخير هو الحكم: لو ظهر منشورك على جهاز غيرك، فالتطبيق حقيقي فعلًا.

## إن تعطّل شيء

| ما تراه | السبب | الحل |
|---|---|---|
| «هذه النسخة غير مربوطة بالخادم» عند فتح التطبيق | بُني بلا مفاتيح | `npm run connect` ثم `npm run make-app` |
| الرمز لا يصل بالـSMS | لم يُضبط مزوّد الرسائل | استعمل الرمز الثابت الذي طبعه `npm run setup`، أو اضبط Twilio |
| لوحة الإدارة لا تظهر | حسابك ليس في `admins` | `npm run admin` |
| «تعذّر الوصول إلى الخادم» | المشروع موقوف (Paused) | افتح supabase.com واضغط Restore |
| رفع صورة يفشل | حاويات الملفات ناقصة | أعد `npm run setup` — يتخطّى ما تمّ ويكمل |
| `npm.ps1 cannot be loaded` على ويندوز | سياسة تشغيل السكربتات | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` ثم أعد فتح النافذة |

للتشخيص من الطرفية: `npm run check:supabase`
ومن داخل التطبيق: لوحة الإدارة ← الإعدادات ← فحص الربط.

## قبل النشر في متجر Google Play

النسخة أعلاه تكفي تمامًا للتوزيع الداخلي. للمتجر تحتاج زيادةً على ذلك:

- `npm run build:android` — ينتج `.aab` وهو ما يقبله المتجر (لا APK).
- حساب مطوّر (25 دولارًا مرة واحدة)، وأيقونة 512×512، وأربع لقطات شاشة،
  و**سياسة خصوصية على رابط عام** (إلزامية).
- استعمل **Internal testing** بدل النشر العام لتطبيق داخلي.

## ما لا يفعله هذا التطبيق — بحكم التصميم

لم تُترك هذه خارج التطبيق سهوًا، ولا تُضاف لاحقًا بغير قرار صريح:

- لا يطلب رتبة ولا رقمًا عسكريًا ولا جهة عمل.
- لا يطلب إذن الموقع، ولا يتتبّع أحدًا، ولا يضع مستخدمًا على خريطة.
- لا يعرض أرقام هواتف المستخدمين لبعضهم.
- لا رسائل خاصة بين المستخدمين، ولا قائمة أعضاء.
- قسم الرماية تنظيمي بحت: مواعيد وتسجيل، بلا أي معلومة فنية أو تشغيلية.
- المحتوى التوعوي عام، بلا تفاصيل أمنية أو تشغيلية.
